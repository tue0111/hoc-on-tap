## Implementation and safety boundaries

- `scripts/v3_refresh.py --plan` uses a native read-only Windows listing in place
  of the cloud connector, saves `work/listing.json`, stages changed/new files and
  verifies source size, modification time and SHA-256 during staging.
- `--apply [plan.json]` verifies the plan is still current. No changes means no-op.
- Core NEW/CHANGED/MISSING or hash drift, including same-size core edits, stops
  OPUS_ONLY. Missing non-core files stop for review; no deletion/retirement assumed.
- NEW IDs append; CHANGED rows append with `supersedes`; old rows are preserved.
  V3 course/learner extraction reads active revisions only.
- Incoming material is classified using path/first-page rules; learner notes and
  rendering by-products remain separated from curriculum.
- Real changes build in an isolated workspace candidate. Only affected partitions
  rebuild; original core data/evals and learner state are not published from it.
- Unique content pauses for a source-hash-bound concept/citation review. Course
  dedupe/validator/frozen gates, external contracts, unaffected-course comparison,
  core regression and freeze checks precede publication. KTCP preserves D2 waiver.
- Citation records keep original legal evidence/status dates; the external builder
  can rebuild from reviewed records without overwriting them from old Wave 5 input.
- Refresh uses a process lock and verifies live dependency mtimes/hashes before
  publication. Existing outputs are backed up; failures restore overwritten files.
  New unreferenced artifacts, candidates and backups are retained, never deleted.
